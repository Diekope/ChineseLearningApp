# Cahier des Charges — AI-Powered Chinese Learning App

## 1. Project Overview

A personal, low-friction app to learn Mandarin Chinese, focused on **speaking, reading, and listening** (not writing/handwriting). It uses AI (local by default, cloud optional) to generate exercises, evaluate pronunciation, and adapt to the learner's level. Starts as a desktop-usable app, with progress that can later continue seamlessly on a phone.

**Learner profile:** complete beginner, no prior Chinese knowledge.

---

## 2. Goals

- Build real ability to **understand spoken Mandarin**, **read basic text (characters + pinyin)**, and **speak with correct tones/pronunciation**.
- Make the first sessions as frictionless and encouraging as possible — the #1 failure mode to avoid is a beginner opening the app, feeling overwhelmed, and quitting.
- Keep the tool personal, private, and free/near-free to run day-to-day.
- Allow the same learning session/progress to resume on a phone later, without rebuilding it as a separate app from scratch.

---

## 3. Functional Requirements

### 3.1 Speaking practice
- Short spoken drills: repeat a word/phrase, get feedback on tones and pronunciation accuracy.
- AI evaluates the recording (via speech-to-text + pronunciation/tone scoring) and gives simple, kind feedback (not a harsh score) — e.g. "close, your 3rd tone dipped too early" rather than "62% correct."
- Progressive difficulty: single syllables → tone pairs → short words → short sentences.

### 3.2 Reading practice
- Graded reading content generated by AI, matched to current vocabulary/level (HSK1 word pool at the start).
- Display in **characters + pinyin**, with the option to toggle pinyin on/off as the learner improves.
- Tap-to-translate / tap-to-hear individual words in a passage.

### 3.3 Listening practice
- AI-generated short audio (via TTS) of vocabulary and sentences at the learner's level, with comprehension questions.
- Adjustable speed (slow/native pace).

### 3.4 Adaptive difficulty & content generation
- The AI generates new exercises on the fly from a leveled vocabulary/grammar pool (starting at HSK1), rather than relying only on static pre-made content.
- Light adaptive logic: struggle with a word/tone → it resurfaces sooner; comfortable with it → it fades out (simple spaced repetition, not a scored system).

### 3.5 Progress tracking (lightweight)
- Tracks what's been practiced and what needs review, purely to drive the adaptive logic.
- Progress is shown simply and calmly (e.g. "things you're getting comfortable with" / "things to revisit") — **not** as scores, streak counters, or percentages designed to create pressure.

### 3.6 Cross-device continuity
- A learning session started on the computer can be picked up later on the phone (same vocabulary state, same "what to review next").
- No requirement for a native phone app upfront — see Section 6.

---

## 4. Explicit Exclusions — What the app must NOT include

These are firm constraints, not just preferences:

- ❌ **No ads.**
- ❌ **No subscriptions or paywalls.** Any cloud AI usage should be pay-as-you-go (cents) at most, never a forced recurring fee.
- ❌ **No tracking/analytics** beyond what's strictly needed locally to run spaced repetition (no telemetry sent anywhere, no third-party analytics SDKs).
- ❌ **No gamification pressure**: no streak counters, XP, badges, leaderboards, or "don't break your streak!" notifications.
- ❌ **No social/community features** (no sharing, friends, chat, comparisons with others).
- ❌ **No handwriting/character-writing practice** (out of scope — reading recognition only, not stroke order/writing).
- ❌ **No childish UI, mascots, or forced cheerfulness.**
- ❌ **No overwhelming complexity.** The single biggest UX risk to guard against: a beginner opening the app and being confronted with too many menus, settings, or a cluttered dashboard on day one. The default view should be: *one clear next action*, nothing else competing for attention.

## 5. AI Architecture — Hybrid (local by default, cloud optional)

| Function | Local (default) | Cloud (opt-in, when available) |
|---|---|---|
| Exercise/text generation | Small local LLM (e.g. via Ollama, quantized 3–8B model) | Larger model (e.g. Claude/GPT via API) for noticeably better, more natural sentence generation |
| Speech-to-text (for pronunciation checks) | Local Whisper (small/base model, e.g. via whisper.cpp) | Cloud STT for higher accuracy tone/pronunciation scoring |
| Text-to-speech | Local Chinese TTS (e.g. Piper or similar open-source voice) | Higher-quality natural cloud TTS voice |
| Translation/word lookup | Local dictionary (CC-CEDICT) + local LLM for context | Cloud LLM for nuanced explanations |

**Behavior:**
- App works fully offline in local mode — this is the default, always-available baseline.
- Cloud mode is a toggle: user can switch it on for a session when better quality matters (e.g. more natural sentences, better pronunciation feedback) and off to save cost / work offline.
- App should clearly show which mode is active, and estimate/track cloud API cost simply (e.g. running total in cents) — no surprise bills.

## 6. Technical Stack Recommendation

Given "no strong preference, recommend best fit," and the desktop-first-then-phone-later requirement:

**Recommended approach: a Progressive Web App (PWA)**
- Single web app codebase (e.g. React or Svelte + a lightweight backend), usable in a desktop browser now, and *addable to a phone home screen* later exactly as-is — no separate native app to build.
- Works well with local AI: local models run either fully in-browser (for small tasks) or via a small local backend service (e.g. a local Python/Node server running Ollama + whisper.cpp) that the web app talks to on localhost.
- Cross-device continuity handled via a lightweight account/sync layer (see Section 7) rather than building two separate apps.

**Suggested components:**
- Frontend: React (or Svelte) + a simple, calm UI (few screens: Practice, Review, Settings).
- Local AI runtime: Ollama (LLM), whisper.cpp (speech-to-text), Piper (TTS).
- Backend (thin): Node.js or Python (FastAPI), mainly for sync + optional cloud AI calls, deployable locally or on a free/cheap tier later.
- Storage: local-first (SQLite or IndexedDB) with optional lightweight sync (e.g. a small self-hosted backend or a free-tier cloud database) when phone access is added.
- Dictionary data: CC-CEDICT (free, open) for word lookups; HSK1 vocabulary list as the initial content pool.

*(This can be adjusted once you confirm whether you want everything self-hosted/local-only, or a small free-tier cloud component for the phone sync.)*

---

## 7. Data & Sync Architecture

- **Phase 1 (computer only):** all data stored locally (no account needed).
- **Phase 2 (add phone access):** introduce a minimal sync mechanism — either:
  - (a) a simple self-hosted sync (e.g. the desktop app also runs a small always-on server on the home network), or
  - (b) a lightweight free-tier cloud sync (just progress data — vocabulary status, review schedule — not audio/recordings) tied to a simple login.
- No third-party data sharing; sync data stays between the user's own devices.

---

## 8. Non-Functional Requirements

- **Simplicity first:** the home screen shows one clear "continue learning" action, not a dashboard of options.
- **Gentle tone:** feedback is encouraging and specific, never scored/graded in a way that feels like a test.
- **Low cost:** local mode should cost nothing to run; cloud mode should be usable in short bursts for cents, never required.
- **Privacy:** recordings and personal data stay local by default; nothing leaves the device unless cloud mode is explicitly on for that session.
- **Fast to start:** from opening the app to starting a practice exercise should take one click/tap.

---

## 9. MVP Scope (build this first)

1. Local LLM generates simple HSK1-level vocabulary + short sentences.
2. Local TTS reads them aloud; local Whisper checks the learner's spoken repetition.
3. Basic reading screen: character + pinyin toggle, tap-to-hear/tap-to-translate.
4. Simple local spaced-repetition logic (no dashboard, no scores).
5. Runs fully offline on the computer.

**Later phases:**
- Cloud mode toggle for higher-quality generation/feedback.
- Phone continuity via sync.
- Expanded vocabulary pool beyond HSK1.
